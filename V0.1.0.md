# DojoMap v0.1.0

## Scope

The goal of v0.1.0 is to deliver a small, production-ready web application that presents an ordered karate curriculum as a clear, responsive progression map.

## Work Items

| ID | Task | Testable outcome |
| --- | --- | --- |
| **DM-001** | Initialize the Next.js project | The application installs, builds, and runs locally with TypeScript enabled. |
| **DM-002** | Clean up the starter application | Default Next.js content and assets are removed, and `/` renders a minimal DojoMap page. |
| **DM-003** | Add project quality tooling | The `lint`, `test`, and `build` commands execute successfully. |
| **DM-004** | Define the curriculum TypeScript model | `Curriculum`, `Rank`, and `Requirement` types exist, and TypeScript validates representative sample data. |
| **DM-005** | Create a sample karate curriculum | A static dataset contains at least five ordered ranks, each with requirements. |
| **DM-006** | Build `RankCard` | Given a rank, the component renders its name and a visual belt or rank indicator. |
| **DM-007** | Test `RankCard` | An automated test verifies that a supplied rank's name and details render correctly. |
| **DM-008** | Build `CurriculumMap` | Given curriculum data, the component renders one `RankCard` for each rank. |
| **DM-009** | Test curriculum ordering | An automated test verifies that every rank renders exactly once and in dataset order. |
| **DM-010** | Add a progression visualization | The interface clearly communicates progression from one rank to the next without requiring explanatory text. |
| **DM-011** | Display curriculum requirements | Each rank displays its requirement categories and content from the dataset. |
| **DM-012** | Make the layout responsive | The curriculum remains usable without horizontal page overflow at phone and desktop widths. |
| **DM-013** | Add basic application identity | The page includes the DojoMap name, a short description, title metadata, and a favicon. |
| **DM-014** | Add empty- and error-safe rendering | Missing or empty curriculum data does not crash the page and produces an intentional state. |
| **DM-015** | Verify the production build | From a clean checkout, the `lint`, `test`, and `build` commands all pass. |
| **DM-016** | Deploy v0.1.0 | A public production URL loads successfully at phone and desktop widths. |
| **DM-017** | Document v0.1.0 | The README explains what DojoMap is, its technology stack, local setup, testing, and the current v0.1.0 scope. |
| **DM-018** | Tag the release | The Git repository contains a `v0.1.0` tag representing the deployed version. |

## Definition of Done

Version 0.1.0 is complete when every work item above meets its testable outcome, the production checks pass from a clean checkout, the deployed application is publicly accessible, and the deployed commit is tagged `v0.1.0`.
