# DojoMap v0.3.0

## Scope

The goal of v0.3.0 is to let students inspect selected techniques without leaving the curriculum journey. A technique detail experience adds useful context and learning resources while preserving the rank map as the application's primary structure.

> **v0.1.0:** The curriculum exists.  
> **v0.2.0:** The curriculum becomes a journey.  
> **v0.3.0:** Techniques gain focused detail.

## Experience Direction

Eligible techniques in the curriculum become intentional controls. Selecting one opens a dedicated detail experience that:

- identifies the selected technique;
- provides a concise description;
- shows the rank or belt where the technique appears;
- renders its supported resources in their defined order; and
- can be dismissed without losing the student's scroll position or curriculum context.

The detail experience may use a modal, sheet, or panel treatment as appropriate for desktop and mobile. It is an in-context layer rather than a separate technique library or a collection of detail routes.

Techniques with internal detail data open the detail experience. Existing curriculum items whose purpose is to open an external resource continue to do so. Items without either destination remain ordinary, non-interactive curriculum content.

## Data Model Evolution

The v0.2.0 model gives each curriculum item one optional resource:

```ts
type CurriculumResource =
  | { type: "external"; url: string }
  | { type: "internal"; slug: string };
```

That model established a doorway, but it cannot yet represent a technique description, multiple resources, or inline notes. DM-046 must evolve it rather than assuming the current structure already satisfies v0.3.0.

The evolved model must preserve these ownership rules:

1. **Curriculum data owns placement.** Ranks and requirements determine where a technique appears.
2. **Technique data owns detail.** A technique definition owns its name, description, and ordered resources.
3. **Rank context is derived.** The detail experience finds rank context through the curriculum relationship instead of copying rank data into the technique definition.
4. **References are stable.** Curriculum technique entries point to reusable technique definitions through a stable ID or slug.
5. **Resources are ordered and repeatable.** A technique may contain zero, one, or several resources without overwriting another resource.

The exact TypeScript representation is decided and implemented in DM-046, but it must support the equivalent of:

```ts
type TechniqueResource =
  | { type: "video"; label: string; url: string }
  | { type: "article"; label: string; url: string }
  | { type: "note"; text: string };

type TechniqueDetail = {
  id: string;
  name: string;
  description: string;
  resources: readonly TechniqueResource[];
};
```

Video and article resources are safe external links in v0.3.0. Notes render as text and are never presented as links. Embedded media players are not required.

## Interaction Ownership

The application must have one intentional source of truth for the selected technique. Opening, switching, and closing details all update that same state. Detail components receive the selected data and dismissal behavior; they do not maintain a second competing selection.

Closing the detail experience restores focus to the control that opened it when possible. It must not reset the curriculum, change ranks, navigate unexpectedly, or lose the current scroll position.

## Out of Scope

Version 0.3.0 does **not** include:

- a browsable or searchable technique library;
- standalone or deep-linkable technique routes;
- form or knowledge detail experiences;
- embedded video players or media hosting;
- student or instructor accounts;
- progress tracking, completion state, or checkmarks;
- authentication;
- a database;
- administration tools;
- curriculum or technique editing and other CRUD operations;
- multiple selectable dojos;
- AI-generated instruction or content; or
- an attempt to map every lesson, milestone, black-belt degree, or lifetime training outcome.

The technique detail experience supplements the current curriculum map. It does not redefine that map as a complete record of a student's martial arts journey.

## Definition of Done

Version 0.3.0 is complete when every work item above meets its testable outcome, technique details work accessibly on phone and desktop widths, existing curriculum behavior remains intact, the production checks pass from a clean checkout, the public deployment is verified, and the deployed commit is tagged `v0.3.0`.

The scope of v0.4.0 will be decided only after v0.3.0 has been deployed and used.
